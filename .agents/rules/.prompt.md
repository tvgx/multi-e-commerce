# Hướng dẫn & Quy tắc Dự án — multi-ecommerce

Mục tiêu: cung cấp quy tắc vận hành, quy trình phê duyệt, quy ước code và hướng dẫn cho cả con người lẫn agent tự động, gói gọn trong thư mục `.agent`.

Phạm vi:
- Source code (apps/, packages/)
- Hạ tầng (k8s/, docker/, infrastructure/)
- CI/CD và quy trình release
- Backup / restore và vận hành
- Quyền truy cập và bảo mật

Nguyên tắc chung (áp dụng cho developers và AI agents):
- Luôn kiểm tra và tuân theo [AGENTS.md](AGENTS.md) trước khi thực hiện thao tác môi trường hoặc quyền.
- Không push trực tiếp lên `main` hoặc branch production; mọi thay đổi phải qua PR.
- Trước thao tác rủi ro (delete, restore, sync → production): luôn chạy `--dry-run`, tạo backup và có 1-2 approvals theo AGENTS.md.
- Không bao giờ ghi/hiển thị secrets trong logs hoặc output công khai. Dùng Azure Key Vault cho production, K8s Secrets cho staging, file `.env` chỉ cho local dev (không commit).

Quy tắc chi tiết cho tác vụ rủi ro (high-risk):
- Hành động cần approval: `shop delete`, `backup restore` (production), `sync config` → production, `health check --auto-fix` (production).
- Quy trình: dry-run → tạo backup tự động nếu cần → tạo PR/issue + nhãn `risk/high` → chờ approvals → thực hiện → log audit.

Quy ước code & CI:
- Chạy lint: `npm run lint` hoặc scripts tương ứng trong `package.json`.
- Chạy test: `npm run test` (hoặc `pnpm test` nếu repo dùng pnpm). PR phải có CI passing.
- Coverage tối thiểu (khu vực quan trọng): 70–80% (thỏa thuận team); các thay đổi business-critical cần test unit + integration.
- Commit message: `type(scope): short description` (ví dụ `feat(api-core): add product pagination`).

Quy trình nhánh & PR:
- Branch: `feature/<short>`, `fix/<short>`, `chore/<short>`.
- PR checklist (bắt buộc):
  - [ ] Tests passing
  - [ ] Lint passing
  - [ ] Changelog / Release notes cập nhật nếu cần
  - [ ] Reviewer được tag (ít nhất 1 review cho dev, 2 cho production-safe changes)
  - [ ] Nếu thay đổi infra → include diff và dry-run output

Quy tắc triển khai (k8s & infra):
- Mọi manifest nằm trong `k8s/` hoặc `apps/*/docker/`.
- Không apply manifest lên production trực tiếp; dùng PR → staging → smoke tests → production.
- Cửa sổ deploy production: 09:00–17:00 UTC (theo AGENTS.md). Trường hợp khẩn cấp: theo quy trình Emergency Override và audit.

Backup & Restore:
- Backup tự động theo CronJob (xem `k8s/jobs/backup-cronjob.yaml`).
- Trước restore production: tạo snapshot backup mới, test restore trên staging, có approval rõ ràng.

Quan sát & Giám sát:
- Metrics/alerts cấu hình trong `monitoring/`.
- Mọi thay đổi ảnh hưởng đến health checks cần có test và không làm tăng false-positive alerts.

Bảo mật & Quản lý secret:
- Production secrets: Azure Key Vault (không commit secret vào repo).
- Staging: K8s Secrets (encrypted in transit), CI: use GitHub Secrets/Azure Key Vault.
- Key rotation: theo tần suất trong [AGENTS.md](AGENTS.md).

Quy tắc dành cho AI Agents (copilot / automation):
- Luôn load `AGENTS.md` và file này (`.agent/.prompt.md`) trước khi đưa ra thay đổi.
- Nếu yêu cầu mơ hồ: hỏi rõ (environment, target branch, acceptance criteria).
- Không commit trực tiếp vào `main` — agents phải tạo PR với mô tả rõ ràng và checklist.
- Mọi thay đổi code do agent sinh ra phải kèm test phù hợp.
- Với thao tác infra/risk: cung cấp dry-run, diff, backup plan và chuỗi các bước rollback.
- Nếu đề xuất thay đổi cấu trúc dữ liệu, mô tả migration và impact (downtime, backward-compatibility).

Tệp nằm trong `.agent`:
- `.agent/.prompt.md` — file này: hướng dẫn chi tiết và rules.
- `.agent/README.md` — tóm tắt nhanh, cách sử dụng prompt.
- `.agent/approval-process.md` — chi tiết quy trình phê duyệt production (nếu cần).

Ví dụ prompt / cách gọi (mẫu):
- "Tạo PR: Thêm API pagination cho products trong `apps/api-core/src/` — gồm unit test và integration test, cập nhật docs, target branch `feature/product-pagination`."
- "Dry-run: sync config từ staging → production, show diff và checklist backup." 

Quy trình cập nhật file này:
- Khi thay đổi nội dung rules, tăng `version:` trong frontmatter, tạo PR với nhãn `docs` và mô tả rõ lý do.

Escalation & Emergency:
- Tuân thủ đường dẫn trong [AGENTS.md](AGENTS.md) (SRE on-call, platform admin cho bypass).
- Emergency override chỉ bởi platform admin với audit và post-mortem.

Ghi chú kết thúc:
File này là nguồn chính cho agent và contributor để biết cách hành xử an toàn và nhất quán trong toàn bộ dự án. Muốn tôi thêm bản tóm tắt (`.agent/README.md`) hoặc chi tiết quy trình phê duyệt (`.agent/approval-process.md`)?
